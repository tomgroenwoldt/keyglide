# Contributing to Keyglide

Thanks for taking the time. Bug reports, new challenge ideas and pull requests
are all welcome.

## Before you start

- **Bugs and small fixes** — just open a PR, no need to ask first.
- **Anything larger** — open an issue or a discussion before writing code, so we
  can agree on the approach before you invest the time.
- **Security issues** — do not open an issue. See [SECURITY.md](SECURITY.md).

## Setting up

[docs/development.md](docs/development.md) has the full local setup. The one
thing that catches everybody: the backend embeds `frontend/dist/` at compile
time, so you have to build the frontend before the backend will compile.

## How we plan larger features

Bigger changes in this repository start as a design document and then an
implementation plan, both under `docs/`. Have a look at
`docs/superpowers/specs/` and `docs/superpowers/plans/` for the shape —
a spec states the goal, the data model, the non-goals and the trade-offs; the
plan turns that into ordered steps.

You do not have to follow this for a bug fix. For a feature that touches the
database or the editor websocket protocol, writing the spec first tends to save a round of
rework.

## Pull requests

Branch off `main` and target `main`.

Before pushing:

```sh
just -f frontend/Justfile check-format   # or `format` to fix in place
just -f frontend/Justfile lint
just -f backend/Justfile lint
just -f editor-service/Justfile lint
cd editor-service && cargo test
```

CI runs the same checks, except for the `editor-service` integration tests:
those drive a real Helix under `bwrap` at paths that only exist inside the
editor-service image, so CI only compiles them. Run them yourself with
`just build-editor-service` if you touch the PTY or sandbox code. Keep the PR focused on one thing — a formatting sweep
mixed into a behaviour change is hard to review.

Write commit messages in the imperative mood, matching the existing history:
`Add streak reset worker`, not `added streak reset worker` or `streaks`.

## Style

**Rust** — `cargo fmt` defaults, `cargo clippy` clean. Route handlers live in
`routes/`, database access in `storage/`, serde types in `schema/`. Anything that
verifies a JWT goes through `verify_token` in `backend/src/schema/claims.rs`;
please do not inline token validation at a call site.

**TypeScript** — Prettier with the repository's `.prettierrc.json` (4 spaces).
Components are lower-kebab-case files exporting a PascalCase component. UI
primitives under `src/components/ui/` are generated by
[shadcn/ui](https://ui.shadcn.com/) via `just -f frontend/Justfile shadcn-add`;
prefer adding one of those over hand-rolling a primitive.

**SQL** — one migration per change, never edit a migration that already ran. RLS
on by default. Details in [docs/development.md](docs/development.md#database-changes).

## Adding challenges

You do not need to touch the code to contribute a challenge — submit it at
[keygli.de/submit](https://keygli.de/submit). Submissions join a queue, and the
highest net-voted one becomes the next day's challenge automatically.
